# 05. UI / UX 설계

디자인 기준: `docs/design/AI Chat Service.html` (다크 톤 · 청록 포인트 · 개발자 도구 느낌의 모노 폰트 보조 정보)

## 1. 디자인 시스템

### 형태
- 모서리: 카드 14px · 입력/버튼 9~10px · 말풍선 14px(꼬리 쪽 4px)
- 등장 애니메이션 `rise`(6px 위로 페이드) 0.25~0.3s, 로딩 점 `blink` 1.2s — `prefers-reduced-motion` 시 비활성
- 최대 폭 1180px, 좌우 여백 `clamp(16px, 4vw, 32px)`

## 2. 화면 구성

### 공통 헤더 / 푸터
```
┌──────────────────────────────────────────────────────────────┐
│ [C] Chatlog (FastAPI · SQLite)     [챗|내 대화 로그]  tester [로그아웃] │  ← 로그인
│ [C] Chatlog (FastAPI · SQLite)                  [로그인] [회원가입]  │  ← 비로그인
└──────────────────────────────────────────────────────────────┘
 ...
 /api/health · 200 OK                          Term Project — AI/SW 기초
```
- 헤더 sticky + blur. 인증 상태에 따라 메뉴가 **완전히 다르게** 표시 (mission §4-2 기능 구분의 시각적 표현)
- `role=admin` 계정에만 세 번째 탭 **[관리자]** 표시
- 푸터의 health 표시는 실제 `/api/health` 호출 결과 (실패 시 "연결 실패" 주황)

### 화면 1: 로그인 / 회원가입 (`/login`, `/signup`)
```
        로그인
        챗봇 질문·응답 기능은 로그인한 사용자만 사용할 수 있습니다.
        ┌────────────────────────────────┐
        │ (가입 완료 안내 — 청록 박스)        │
        │ 아이디   [username          ]   │
        │ 비밀번호 [••••••••          ]   │
        │ [400] 아이디와 비밀번호를…  (주황)  │
        │ [          로그인          ]    │
        │    아직 계정이 없나요? 회원가입      │
        └────────────────────────────────┘
        POST /api/auth/login · bcrypt 해시 저장 · HttpOnly 세션 쿠키
```
| 상호작용 | 동작 |
|----------|------|
| 제출(Enter/버튼) | 클라이언트 검증 → 실패 시 `400` 칩 + 메시지, 요청 안 보냄 |
| 서버 오류 | 상태코드 칩(401/409) + 서버 메시지, 비밀번호 필드 비움 |
| 제출 중 | 버튼 "처리 중…" + disabled (중복 제출 방지) |
| 가입 성공 | `/login` 이동, "가입이 완료되었습니다" 안내, 아이디 자동 입력 |
| 로그인 성공 | 원래 가려던 경로(`state.from`) 또는 `/chat` |
| 로그인 상태에서 접근 | `/chat` 으로 리다이렉트 |
| 접근성 | `label` 연결, `autocomplete=username/current-password/new-password`, 오류 `role="alert"` |

### 화면 2: 챗 (`/chat`) — 로그인 필수
```
┌─ 새 대화  context: 최근 5턴 ─────────── ● 연결됨 ┐  ┌ 응답 시뮬레이션 ───────┐
│ ┌────────────────────────┐                       │  │ [정상 응답]   (선택됨)  │
│ │안녕하세요. 무엇을…        │  14:02                │  │ [AI_TIMEOUT (503)]     │
│ └────────────────────────┘                       │  │ [AI_ERROR (503)]       │
│                        ┌──────────────────┐      │  │ 실패 시에도 서비스는…     │
│                        │ 배포 방법 알려줘   │ 14:03 │  └────────────────────────┘
│                        └──────────────────┘      │  ┌ 서버 로그 ─────────────┐
│ ┌──────────────────────────┐                     │  │ INFO request_received… │
│ │ 현재 응답이 지연되고 있어요 │ ← 주황 오류 말풍선     │  │ INFO ai_call_start …   │
│ │ 503 · AI_TIMEOUT          │                     │  │ WARN ai_call_failed …  │
│ └──────────────────────────┘                     │  │ INFO db_save_success … │
│ ● ● ●  (응답 대기)                                 │  └────────────────────────┘
├──────────────────────────────────────────────────┤
│ [질문을 입력하세요 — Enter 전송, Shift+Enter 줄바꿈 ] [전송] │
│ POST /api/chat                          14 / 1000 │
└──────────────────────────────────────────────────┘
```
| 요소 | 동작 / 이유 |
|------|-------------|
| 진입 시 | `/api/me/chats?limit=20` 으로 **이전 대화 복원** → 새로고침해도 대화가 사라지지 않음 |
| 말풍선 3종 | 사용자(우측·청록) / 봇(좌측·회색) / 오류(좌측·주황 + `상태 · 코드`) |
| 전송 | Enter 전송, Shift+Enter 줄바꿈, **한글 IME 조합 중 Enter 무시**(마지막 글자 중복 방지) |
| 낙관적 표시 | 사용자 말풍선을 즉시 추가 → 로딩 점 3개 → 응답/오류 말풍선 |
| 입력 검증 | 공백만 / 로딩 중 → 전송 버튼 비활성, 1000자에서 입력 차단 + 카운터 주황 |
| textarea | 내용에 맞춰 최대 140px 까지 자동 높이 |
| 오류 후 | 입력창 포커스 복귀 → 바로 재시도 가능 (서비스 유지 체감) |
| 401 수신 | 전역 이벤트로 로그인 화면 이동 (세션 만료 대응) |
| 네트워크 실패 | `NETWORK · NETWORK_ERROR` 말풍선 + 헤더 점 "연결 끊김" |
| 자동 스크롤 | 새 메시지/로딩 시 하단으로 부드럽게 |
| 응답 시뮬레이션 | `demo_mode=true` 일 때만 표시. 선택 상태는 청록 테두리, 하단 메타에 `simulate=timeout` 노출 |
| 서버 로그 패널 | 요청 완료마다 `/api/me/server-logs` 갱신. 레벨 색상(WARNING 주황, ERROR 적색). 파이프라인 단계를 사용자가 눈으로 확인 |
| `aria-live="polite"` | 스크린리더가 새 응답을 읽어줌 |

### 화면 3: 내 대화 로그 (`/logs`) — 로그인 필수
```
내 대화 로그                                    ┌총 기록┐ ┌평균 응답┐ [새로고침]
GET /api/me/chats — 로그인한 사용자 본인의 기록만    │  13  │ │  0.4s  │
┌──────────────────────────────┐ ┌──────────────────────────────┐
│ #13 user_id=1 AI_TIMEOUT 15002ms   2026-09-14 11:45 │ │ #12 user_id=1 402ms ...        │
│ QUESTION  긴 글 요약해줘         │ │ QUESTION  내가 방금 뭘 물어봤지? │
│ ─────────────────────────── │ │ ─────────────────────────── │
│ ANSWER  응답 실패 — 오류 안내 반환 │ │ ANSWER  직전에 '배포 방법…'     │
└──────────────────────────────┘ └──────────────────────────────┘
```
- 반응형 그리드 `minmax(min(100%, 380px), 1fr)` → 모바일 1열
- 실패 기록은 오류 코드 태그 + 주황 안내 문구
- 비어 있으면 점선 박스 "아직 저장된 대화가 없습니다."

### 화면 4: 관리자 (`/admin`, `/admin?user=<id>`) — role=admin 필수
```
관리자                                  ┌사용자┐┌대화┐┌실패┐┌평균 응답┐ [새로고침]
GET /api/admin/* — 관리자만 …            │ 150 ││148 ││ 35 ││  0.4s   │
┌ [아이디 검색        ] 150명 ┐  trk_1a2b3c4d                         [전체|성공|실패]
│▌trk_1a2b3c4d               │  user_id=42 · 가입 2026-09-14 14:10 · 평균 0.4s · 3건
│  대화 3  실패 1   09-14 14:10│  ┌────────────────────┐ ┌────────────────────┐
│ admin [admin]               │  │#301 user_id=42 AI_ERROR│ │#300 user_id=42 402ms │
│  대화 0          활동 없음   │  │QUESTION 오류 질문     │ │QUESTION 내가 방금…   │
│ tester                      │  │ANSWER 응답 실패 …     │ │ANSWER 직전에 …       │
│  대화 12 실패 4  09-14 12:54 │  └────────────────────┘ └────────────────────┘
└─────────────────────────────┘
```
| 요소 | 동작 / 이유 |
|------|-------------|
| 통계 4칸 | 서비스 전체 규모·장애 비율을 한눈에 (`/api/admin/stats`) |
| 사용자 목록 | **최근 활동 순** 정렬 → 방금 문제가 생긴 사용자가 위. 실패 수는 주황 강조, admin 은 청록 태그 |
| 검색 | 입력 250ms 후 조회(디바운스), 결과 수 `N명` 표시, 없으면 "검색 결과가 없습니다." |
| 선택 표시 | 좌측 청록 막대 + 배경, `aria-pressed` |
| 대화 카드 | 내 대화 로그와 **같은 `LogCard`** → 사용자·관리자 화면의 정보 구조 일치 |
| 상태 필터 | 전체/성공/실패 토글 → 실패만 모아 장애 추적 |
| URL 동기화 | `?user=<id>` → 새로고침·뒤로가기·링크 공유 시 같은 사용자 |
| 빈 상태 | 미선택 "왼쪽 목록에서 사용자를 선택하면…", 필터 결과 없음 "표시할 대화가 없습니다." |
| 권한 없음 | 일반 사용자는 탭이 없고, 주소 직접 입력 시 `/chat` 으로 이동 |
| 반응형 | 좁은 화면에서 사용자 목록 위, 대화 아래 1열 스택 |

## 3. 반응형
| 폭 | 레이아웃 |
|----|----------|
| ≥ 900px | 챗 영역 + 우측 패널 2단 |
| < 900px | flex-wrap 으로 패널이 챗 아래로 이동 |
| ≤ 560px | 헤더: 브랜드 1줄, 탭/사용자 2줄. 챗 높이 = 화면 - 220px |
| 관리자 화면 < 760px | 사용자 목록(위) · 선택 사용자 대화(아래) 1열, 통계 칸 줄바꿈 (검증 B26, `09-admin-mobile.png`) |

## 4. 오류 메시지 원칙
1. **무슨 일이 일어났는지 + 사용자가 할 일**을 한 문장으로 ("지연되고 있어요. 잠시 후 다시 시도해 주세요.")
2. 기술 코드는 작게 모노 폰트로 병기 (`503 · AI_TIMEOUT`) → 사용자는 문장, 개발자/평가자는 코드
3. 로그인 실패는 아이디/비밀번호 중 무엇이 틀렸는지 알리지 않음 (보안)
4. 빨강 대신 채도 낮은 주황 → 다크 톤 분위기 유지, 공포감 완화
